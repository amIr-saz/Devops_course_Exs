====================================================================
                      TEXT EXPLANATION
====================================================================

1. CONTROL NODE (گره کنترل):
   - سیستمی است که Ansible روی آن نصب شده و دستورات از آنجا اجرا می‌شوند.
   - شامل فایل‌های Inventory (لیست سرورها)، Playbooks (دستورالعمل‌های YAML) و Modules (کدهای اجرایی) است.
   - در این معماری، کنترل نود دستورات را به سمت سرورها "Push" می‌کند.

2. MANAGED NODES (گره‌های مدیریت‌شده):
   - سرورها یا ماشین‌های مقصدی هستند که توسط Ansible مدیریت می‌شوند.
   - در این معماری، هیچ نرم‌افزار اضافه‌ای (Agent) روی این سرورها نصب نمی‌شود.

3. AGENTLESS ARCHITECTURE (معماری بدون Agent):
   - Ansible برای ارتباط با سرورهای لینوکسی از SSH استفاده می‌کند.
   - برای سرورهای ویندوزی از WinRM استفاده می‌کند.
   - تنها پیش‌نیاز برای سرورهای لینوکسی، وجود Python است. برای ویندوز، PowerShell کافی است.

4. PUSH MODEL (مدل هل دادن):
   - برخلاف ابزارهایی مثل Puppet که مدل Pull دارند (سرورها خودشان تنظیمات را دریافت می‌کنند
)، Ansible دستورات را از Control Node به سمت Managed Nodes هل می‌دهد.
