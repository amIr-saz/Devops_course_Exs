
# مفاهیم اولیه Git

## Repository (مخزن)
ریپازیتوری یا مخزن، پوشه‌ای است که توسط Git مدیریت می‌شود (با دستور `git init` ایجاد می‌شود). این پوشه یک پوشه مخفی به نام `.git` دارد که تمام تاریخچه تغییرات، کامیت‌ها و تنظیمات پروژه در آن ذخیره می‌شود. با این کار Git می‌تواند تغییرات فایل‌ها را در طول زمان ردیابی کند.

## Atomic Commit (کامیت اتمی)
کامیت اتمی یعنی هر کامیت فقط و فقط شامل **یک تغییر منطقی** باشد. مثلاً اگر یک باگ را برطرف می‌کنید، فقط فایل‌های مربوط به همان باگ را کامیت کنید. فایل‌های نامرتبط را در کامیت‌های جداگانه ثبت کنید. مزیت این کار این است که اگر بعداً بخواهید تغییری را برگردانید (Revert) یا تاریخچه را بررسی کنید، دقیقاً می‌دانید هر کامیت چه کاری انجام داده است.

## Nested Repository (ریپازیتوری تو در تو)
ایجاد یک ریپازیتوری داخل ریپازیتوری دیگر یک اشتباه رایج است. وقتی داخل یک پوشه که قبلاً `git init` شده، پوشه جدیدی بسازید و دوباره `git init` بزنید، گیتِ اصلی (Parent) فایل‌های داخل آن پوشه را نادیده می‌گیرد و آن را به عنوان یک Submodule می‌بیند. 
**چرا نباید این کار را کرد؟**
چون گیتِ والد فقط به یک «هش کامیت» از ریپوی داخلی اشاره می‌کند. اگر پروژه را روی GitHub پوش (Push) کنید، فایل‌های داخلی آپلود نمی‌شوند و شخص دیگری که پروژه را کلون می‌کند، آن پوشه را خالی دریافت می‌کند. برای جلوگیری از این مشکل یا باید پوشه `.git` داخلی را حذف کرد یا از ابزار رسمی `git submodule` استفاده کرد.
