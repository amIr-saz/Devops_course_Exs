# تفاوت Working Directory و Staging Area در Git

برای درک بهتر، گیت را مانند یک کارگاه نجاری در نظر بگیرید که سه بخش اصلی دارد:

## ۱. Working Directory (پوشه کاری)
این همان پوشه‌ای است که شما روی سیستم‌تان می‌بینید و فایل‌ها را داخل آن ویرایش می‌کنید. وقتی یک فایل متنی را باز می‌کنید و کدی به آن اضافه می‌کنید و ذخیره (Save) می‌کنید، آن تغییر در Working Directory اتفاق افتاده است.
*   **وضعیت:** گیت تغییرات این پوشه را می‌بیند، اما هنوز آن‌ها را تایید نکرده است. (در `git status` با رنگ **قرمز** نشان داده می‌شوند و Unstaged هستند).

## ۲. Staging Area (ناحیه آماده‌سازی / Index)
این یک منطقه واسط و موقت است. وقتی شما دستور `git add <file>` را می‌زنید، فایل از Working Directory به Staging Area منتقل می‌شود. در واقع شما به گیت می‌گویید: "من این تغییرات را تایید می‌کنم و می‌خواهم در کامیتِ بعدی لحاظ شوند".
*   **وضعیت:** تغییرات اینجا در صف انتظار برای ثبت نهایی هستند. (در `git status` با رنگ **سبز** نشان داده می‌شوند و Staged هستند).

## ۳. Repository (مخزن)
اینجا محل ذخیره‌سازی دائمی تاریخچه است. وقتی دستور `git commit -m "..."` را می‌زنید، تمام فایل‌های موجود در Staging Area برای همیشه در Repository ثبت می‌شوند.

## خلاصه و مثال:
تصور کنید در حال عکاسی هستید:
- **Working Directory** مانند دنیای واقعی است که افراد در آن مشغول کار هستند.
- **Staging Area** مانند فریم دوربین است. شما افراد را در کادر دوربین تنظیم می‌کنید و می‌گویید "فقط این افراد در عکس باشند".
- **Commit** همان لحظه‌ای است که دکمه شاتر را می‌زنید و عکس برای همیشه ثبت می‌شود.

**نتیجه:** 
دستور `git add` تغییرات را از Working Directory به Staging Area می‌برد و دستور `git commit` آن‌ها را از Staging Area به Repository منتقل می‌کند.
