# تفاوت git revert و git reset

هر دو دستور برای برگرداندن تغییرات استفاده می‌شوند، اما روش و کاربرد آن‌ها متفاوت است:

- **`git reset`:** تاریخچه را **بازنویسی** می‌کند. کامیت‌های بعدی را حذف می‌کند و انگار هرگز اتفاق نیفتاده‌اند. این کار برای پروژه‌های **شخصی و محلی** مناسب است.
- **`git revert`:** تاریخچه را تغییر نمی‌دهد. یک **کامیت جدید** ایجاد می‌کند که دقیقاً برعکس کامیت مورد نظر است (تغییرات را خنثی می‌کند). کامیت‌های قبلی در تاریخچه باقی می‌مانند.

## چه زمانی از کدام استفاده کنیم؟
- اگر پروژه‌ای را به اشتراک گذاشته‌اید (Push کرده‌اید) و دیگران آن را Pull کرده‌اند، **هرگز از Reset استفاده نکنید** چون تاریخچه را برای همه به هم می‌ریزد.
- برای پروژه‌های اشتراکی (Shared Repositories) همیشه از **Revert** استفاده کنید، چون یک کامیت جدید و امن به تاریخچه اضافه می‌کند و برای همه قابل درک است.
