# توضیح انواع git reset

دستور `git reset` برای جابه‌جایی HEAD به یک کامیت قبلی استفاده می‌شود، اما سه حالت آن رفتار متفاوتی با فایل‌ها دارند:

1. **`git reset --soft HEAD~1`:**
   فقط `HEAD` را به کامیت قبلی منتقل می‌کند. تغییرات **در ناحیه Staging** باقی می‌مانند (آماده کامیت مجدد). هیچ فایلی از بین نمی‌رود. (برای ادغام چند کامیت کوچک عالی است).

2. **`git reset --mixed HEAD~1` (حالت پیش‌فرض):**
   `HEAD` را به عقب می‌برد و تغییرات را از **Staging خارج می‌کند**، اما تغییرات فایل‌ها در **پوشه کاری** حفظ می‌شوند (Unstaged). (برای زمانی که کامیت زودهنگام زده‌اید و می‌خواهید دوباره فایل‌ها را بررسی کنید).

3. **`git reset --hard HEAD~1`:**
   خطرناک‌ترین حالت! `HEAD` را به عقب می‌برد و **تمام تغییرات را در Staging و Working Directory پاک می‌کند**. فایل‌ها به حالت آن کامیت برمی‌گردند و تغییرات بعد از آن برای همیشه از بین می‌روند. (با احتیاط استفاده شود).
